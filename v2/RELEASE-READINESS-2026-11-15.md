# V2.0 上线准备｜独立迁移验收门禁（2026-11-15）

**结论：生产上线仍被阻断（BLOCKED），不是已经具备正式切换条件。**

本轮只改动隔离开发分支，新增**只读合成数据迁移审计**和自动化检查，专门防止“业务界面测试通过，就误以为旧版全量资料已迁移”的错误。此项检查成功仅意味着阻断逻辑正确工作，**绝不表示可以发布正式版**。

## 已核实旧版 V1.5.7 的数据位置

- 当前仓库旧版 app.js 使用 localStorage["personalWorkbench"] 保存业务 JSON。
- 旧版 app-v151t.js 使用当前域名的 IndexedDB "personal-workbench-originals" / object store "files" 保存文件原件；收件箱 inbox 保存文件元信息。**单独拿到本地 JSON 不等于拿到原件**。
- 项目和合同相关字段由 app-v138t.js、app-v139t.js、app-v140t.js 管理，主要包括 contractProjectsV138、businessProjectsV140、contractActionsV139、projectFilesV150。
- V1 还有任务、随手笔记、商机、财务、生活等业务 JSON 子字段，真实设备是否有这些字段/文件仍需要单独只读核验。用户可能在 Safari、主屏幕 PWA 或不同域名中有不同数据，不能拿某一个域名的数据代表整个设备。

## 本轮新增的自动化证明

release-readiness-audit.cjs 是纯函数，只接收**由测试主动提供**的合成 JSON 和二进制文件。它不调用 HTTP、LocalStorage、IndexedDB 或生产系统，不执行迁移和写入。

- 构建源快照 SHA-256、原件逐文件 SHA-256、数量/总字节清单。
- 对照历史合同项目、业务项目、行动明细、收件箱元数据、项目原件引用，拦截重复 ID、孤儿引用、缺少原件、原件大小不一致。
- verifyExactShadow 只读核对复制到另一个独立数据容器的 JSON 和**原件字节**；即使只错一个字节也停止。
- 用现有 WorkbenchBusiness.fromLegacy 执行合成导入试验，明确识别**它目前仅建立医院/项目结构**，并不能恢复 inbox、真实原件和旧版其他生活/财务/任务等资料。绝不把这一转换函数当作完整 V1→V2 迁移器。
- 测试会刻意制造损坏文件、缺文件、重复记录、孤儿关联、未映射历史业务模块，并确认全部被阻断；检查前后的源 JSON/原件保持一致。
- 新 GitHub Actions 工作流 v2-release-readiness.yml 对本隔离分支持续执行，**contents: read 且没有部署/迁移凭据**，成功标志 RELEASE_READINESS_GUARD_PASS，报告仍明确 BLOCKED_NOT_FOR_PRODUCTION。

## 正式上线仍有必须完成的门槛

1. **真实设备和域名上的完整来源清单**：仅在最终获得用户明确许可后，执行只读导出，识别 Safari/PWA/原域名/其他 V2 数据来源；不能隐式合并或覆盖。
2. **完整兼容转换器**：保留全部 V1 业务子模块、金额、项目状态、历史时间线、收件箱/资料及二进制原件；明确无法自动对应的内容并停下人工核对。
3. **加密存储与可恢复备份正式集成**：现有独立公共预览端只是 PIN 防窥，业务 IndexedDB 尚未整体加密；此前的加密/原件分块/设备身份实验仍是合成 PoC，不得冒充正式安全交付。
4. **生产发布与恢复演练**：在全新隔离库做逐条及逐字节恢复、断网/并发/错误密钥的失败回滚、V1.5.7 保留可退回；正式生产部署须单独得到用户确认。
5. **真实 iPhone Safari/添加到主屏幕 PWA 终验**：特别检查相机、麦克风、后台切换、离线重新打开、隐私验证。

当前可以继续自动完成合成代码与 CI，不需要用户进行开发操作。**没有收到真实资料迁移及正式发布的单独授权前，禁止移动真实数据、覆盖正式版本、关闭旧版本或使用公有预览保存医院资料。**
