# V2.0｜本机双设备端到端加密同步原型安全与一致性审核（2026-11-13）

## 结论边界

**本轮是本机合成数据的双浏览器 E2E 加密同步协议测试，不是已经让真实 Cloudflare Worker、两部真实 iPhone 或正式工作台支持加密同步。**

新增 `v2/privacy-e2e-cloud-poc.js` 与 `v2/test-privacy-e2e-cloud-poc.cjs`，仅 `127.0.0.1/localhost` 且显式合成测试标记生效，复用已通过本机加密与差量日志验证的 `WorkbenchDeltaCryptoPOC` 以及真实 `business-core.js` 业务数据结构。两个不同浏览器上下文使用**各自独立的 IndexedDB 和数据密钥恢复库**，通过同一个 Node 本机模拟服务传输 AES-GCM 密文信封。

本次没有向生产、原 staging、Cloudflare public Preview 上传任何资料，也不创建/修改真实医院记录、收费服务、真实用户令牌或持久工作台身份。**合成模拟器中的 TEST bearer 和共享传输密钥由测试随机生成、只在本轮内存中使用**，不等同于生产级手机设备配对或秘密管理。

## 实现的协议行为

1. 合成客户端读取完整且经过内部认证的逐对象加密本机归档，然后再用独立256位 AES-GCM 传输密钥二次封装。传给模拟云端的是 `{iv,tag,ciphertext}`；云端只计算认证信封 SHA-256、存储历史、不接触真正业务名或附件明文。
2. 发送格式沿用原 Worker 协议的 `expectedRevision / expectedHash / hash / payload` 以及按64KiB以内块上传 `/sync/uploads/<upload-hash>/<part-index>` 和最终 `PUT /sync` manifest。模拟服务在完整性与CAS检查通过前不写新的正式版本。
3. 新客户端首次从云端接收时只**恢复到全新随机 IndexedDB**，不会直接覆盖本机库；必须显式批准，才能从旧设备/空本机库切换。
4. 本机离线编辑仅保留已加密业务对象、可重放差量队列及原始文件块；重新连网时读取远端版本。
5. 双端修改不同医院时，云端远端更新先被恢复到**第三个隔离库**，双方原记录不变。用户明确批准后，只合并可证明没有重叠修改、没有新远端附件的对象；仍利用远端最新版本CAS提交。相同UUID不同内容、远端新增本机没有的附件、缺失对象、未知字段都不允许自动并入。
6. 双端编辑同一医院不同字段时也保守拒绝自动合并，保存两份数据供真实用户逐字段确认；**不保证所有业务冲突都自动解决**。
7. 如果最终上传已成功而响应丢失，重试先读云端确认与原缓存密文hash一致，不重复增加版本。若网络在上传中途断开，重试重复上传相同密文块并确认上传ID；只有完整manifest和CAS匹配才增加版本。
8. 支持按 `GET /sync/history/<revision>` 恢复旧云端加密历史到新的独立数据库；恢复不会删除或者自动切换当前工作数据库。
9. 非回环URL、错误身份/错误传输密钥、被改动的远端信封hash都会失败关闭，本机记录与队列原样保留。

## 自动化试验内容

- **两个真正隔离的浏览器上下文**在同一个本机模拟服务连接，服务维护独立内存中的CAS修订号与不可变历史。
- A上传合成医院及 **512KiB+21B 原始附件**，B初次恢复；核查字节 SHA-256 与合成医院字段一致。
- A断网编辑医院A，B在线编辑医院B先上传；A恢复网络识别冲突、恢复远端隔离副本、不能不经授权自动覆盖；用户在合成测试中批准安全无重叠合并，再提交云端，B显式确认版本接管。
- A/B都更改初始医院同一ID的记录，冲突分支禁止自动合并；A/B各自数据保存，人工处理为未来门槛。
- 查询版本1的历史备份，恢复原始医院和完整附件；其他本机后续修订完全不变。
- 模拟上传全部完成但最终ACK丢失，下一次只确认同一密文包，云端历史修订不重复。
- 模拟在上传若干分片后掉线，重发已接受分片必须幂等，历史不会出现未完成版本。
- 模拟远端哈希错误、错误传输密钥、错误bearer、生产样式URL等均拒绝访问和静默覆盖。
- 测试检测真实发出 HTTP multipart 请求，服务快照内部仅允许看到密文字段，不出现医院名称、附件名、恢复密码或bearer明文。

## 必须严守的未完成内容

1. **服务是localhost Node模拟，并非线上 Cloudflare Worker**。虽然字段、哈希、CAS、分片传输匹配现有隔离 Worker 协议形式，但还必须对真实独立合成 Worker 做带过期密钥与撤销的远端验收，不能把本机模拟通过宣称为真实双手机云端已可用。
2. 传输密钥目前通过测试环境注入两端，**没有**完成真实 iPhone 的设备配对、密钥安全交换、硬件背书解封、凭据管理、吊销、遗失手机恢复。
3. 每次云端推送上传完整**二次加密归档**，离线队列在本机已是对象增量，但网络传输还不是对象级增量；大附件与历史数量会造成明显上行带宽压力。正式版必须设计可验的对象增量云端传输、密钥重封装及分块按内容寻址后再开放。
4. 模拟合并只处理没有重叠修改和没有新增远端附件的场景；同一业务对象双方更改、医院名称重复、关联项目冲突、远端新增附件等仍需要人工审查、完整原件及历史版本保留。
5. 这不是通过独立第三方安全审计。真实 iPhone Safari/PWA 的Face ID或密码认证密钥保管、离线寿命、设备存储空间配额、恢复后数据核对、跨应用缓存仍有独立验收门槛。
6. 当前数据来源仅随机合成测试，**任何真实V1.5.7数据迁移、正式部署、生产密钥变更都必须用户明确授权**。
