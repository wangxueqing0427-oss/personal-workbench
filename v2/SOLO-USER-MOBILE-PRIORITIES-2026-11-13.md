# V2.0 单人手机使用优先方案（2026-11-13）

## 用户明确调整的交付优先级

当前工作台主要由本人日常使用，不按公开 SaaS、多用户医疗信息平台或商业化系统规划。优先开发**随时能从 iPhone 录入、查看、检索、跟进医院/项目、拍照存原件、登记耗材、掌握业务节点**的功能；不再把复杂多设备身份体系、额外的密码协议和安全认证当作功能上线的前置工作。

**但资料真实存在业务敏感性，必须保留最小的必要保障**：进入 App 后的本机遮挡锁、可以验证并恢复的完整备份、文件原件逐字节保留、离线时不可静默丢数据、同步冲突不允许覆盖、正式升级前只读验证。无需增加付费 API 或服务，不允许未经确认自动迁移真实历史库。

## 本轮已实现（独立 V2 开发分支）

1. 医院与项目快速筛选：医院正式名称/旧别名、科室、联系人/电话、设备品牌/型号、项目名称、下一步、状态等关键词本机检索；可进一步按状态筛选，输入时不重新渲染输入框，手机键盘焦点保留。
2. 修复医院正式名称编辑：按既有医院 ID 准确修改、旧名称作为别名保留、原联系人和项目关联不变；其他医院的名称或别名冲突、失效医院 ID 均直接拒绝，不做错误合并。
3. 耗材单据的拍照与文件一键入口：从订单点上传时自动关联订单所属项目；文件原件、关联项目和订单一起保存；拍照与文件选择互斥，避免误传之前选的文件；首页原有“拍照 / 上传”入口保留。
4. 为手机业务新增独立 Playwright Chromium/WebKit 自动化，真实操作表单、搜索、附件、订单关联、文件原字节和页面刷新。最新 [60/60 绿色测试](https://github.com/wangxueqing0427-oss/personal-workbench/actions/runs/43408677938)；兼容旧数据/加密存储原型的 [434/434回归](https://github.com/wangxueqing0427-oss/personal-workbench/actions/runs/43408882330) 成功；[独立 Preview 构建检查](https://github.com/wangxueqing0427-oss/personal-workbench/actions/runs/43408677945) 成功。
5. 新功能和修改仅在 `dev/v2-preview-isolated-20261111`；不读取 V1.5.7 真实库、不改 `main`，不写原 staging 或生产系统。独立 Preview 的演示数据为合成内容。

## 下一次继续时优先开发的功能（按日常使用价值）

- **优先**：手机首页的“今天要办/等待反馈/已逾期”任务列表优化：可快速修改下一步、跟进日期、联系人反馈，不需要逐层进入多级表单。
- **优先**：医院/项目资料跟进时间线与拍照上传联动：拍照上传时可以直接写一条备注，关联本次医院、项目、订单和照片原件。
- **其次**：耗材采购、开票、回款与库存的简单概览与筛选，尤其是待确认、待开票、未回款业务。
- **其次**：iPhone Safari/PWA 的真实本人验收流程，先验证安装桌面、拍照、重新打开、离线记录、文件分享与备份恢复。
- **延后**：公开服务端多租户权限、复杂设备 PKI、硬件密钥签发、团队共享/商业化功能；如未来用户需要共享或公开使用再讨论。

## 上线门槛

- 提交源码、Chromium 与 WebKit 的真实手机布局和表单自动化全部通过，预览版版本来源明确。
- 正式 V1.5.7 和真实业务数据保持原样，直到用户亲自批准迁移；必须先有可核对并能恢复的备份。
- 没有真实 iPhone 测过的项目不宣称已完成真机验收；独立演示 Preview 不承载真实客户资料。
